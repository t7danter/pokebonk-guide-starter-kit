# Contributing

Useful contributions make a claim easier to verify or a resource easier to use. Submit a focused issue or pull request; keep unrelated corrections separate.

## A good correction includes

1. The affected repository file or public guide URL.
2. The current statement and a proposed replacement.
3. A public source and precise section or timestamp.
4. Observation date, review date, game build, language, mode, difficulty, and relevant modifiers where known.
5. The boundary of the evidence: displayed wording, gameplay observation, translation, secondary report, repeated comparison, or interpretation.
6. What remains unknown and why the correction is justified.

Use `unknown` when a field cannot be established. Do not infer a game version from a guide's review date. If relying on a guide instead of original evidence, say so explicitly.

## Scope

Welcome: corrected navigation, clearer checklists, source-backed explanations, better template definitions, and reproducible observation methods.

Please do not submit promotional link lists, invented measurements, unsupported rankings, copyrighted asset packs, game implementations, credentials, save exports, account identifiers, or private local files. Do not claim official affiliation. Do not describe external links as guaranteeing search-engine treatment.

No screenshots or recordings are included in this initial project. Before proposing any media, establish permission to redistribute it and review it for private information. A link to a public source is usually sufficient for a correction.

## Review checklist

- [ ] Sources support the exact claim being made.
- [ ] Original observations and guide reports are distinguished.
- [ ] Conditions, units, and uncertainty are preserved.
- [ ] Translations and naming references are labeled.
- [ ] Example rows remain unmistakable placeholders.
- [ ] Relative links resolve and external links point to the intended source.
- [ ] No private data, secrets, or unlicensed third-party material are added.
- [ ] Original contributed material can be shared under the repository's MIT License.

There is no code build to run. Preview the Markdown, inspect CSV formatting where applicable, and check the changed links. Report access failures instead of marking an unreachable page confirmed.

Be specific and respectful. Discuss the evidence rather than the person who submitted it.
