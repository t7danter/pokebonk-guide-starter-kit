# Player checklist

Use this as a short worksheet, not as a promise of an optimal build. The linked [beginner guide](https://pokebonkgame.com/guide/) and [FAQ](https://pokebonkgame.com/faq/) provide topic-specific reading.

## Before a run

- [ ] Pick one question or learning goal, such as understanding a particular upgrade offer.
- [ ] Read your chosen character's [documented profile](https://pokebonkgame.com/wiki/).
- [ ] Record build, mode, difficulty, language, character, and persistent upgrades when visible.
- [ ] Copy [run-note.md](../templates/run-note.md) into your own notes and replace its placeholders.
- [ ] Decide how you will identify the relevant source without publishing private information or unlicensed assets.

## When choosing an upgrade

- [ ] Read the full effect text, including its conditions and units.
- [ ] Compare any stated damage class or affected moves with your current kit.
- [ ] Distinguish displayed price, owned count, stack limit, and effect value.
- [ ] If consulting the [item directory](https://pokebonkgame.com/items/), expand the observation and source context instead of relying only on the item name.
- [ ] Write down why you chose the offer. A reasoned preference can still be untested.

## When checking progression or controls

- [ ] Write the exact label shown in the current interface.
- [ ] Keep similarly named purchases or unlocks in separate records.
- [ ] Follow the action prompt on your own screen; a partial key reference is not a complete control scheme.
- [ ] Record what the objective or result screen actually says before calling an encounter a complete win.

## After a run

- [ ] Record the outcome, including failures and interruptions.
- [ ] Preserve the context of each observation; do not combine different modes or builds into one account.
- [ ] Separate what you saw, what a guide says, and what you infer.
- [ ] Leave values you did not capture as `unknown`.
- [ ] For a comparison, note which conditions changed and which could not be controlled.
- [ ] Recheck the cited page before sharing a claim with a precise number.

For a repeatable comparison, continue with the [evidence workflow](evidence-workflow.md). To report a guide correction, follow [CONTRIBUTING.md](../CONTRIBUTING.md).
