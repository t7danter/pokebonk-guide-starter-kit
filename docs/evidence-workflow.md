# Evidence and comparison notes

## Match the claim to its evidence

| Evidence type | What it can support | What it cannot establish alone |
| --- | --- | --- |
| Current game interface | Wording and values displayed in that context | Hidden formulas or actual average performance |
| Gameplay observation | An event in a specified run | A universal rule across builds or modes |
| Repeated comparison | A result under the reported conditions | An unconditional best choice for every player |
| Published guide | What that guide reports and cites | Independent confirmation of its underlying evidence |
| Translation or naming reference | A proposed wording or name correspondence | An effect, price, or official English game label |
| Personal recommendation | A player's preference and reasoning | A tested ranking or community consensus |

These are practical review categories for this repository. They are not certification of any game mechanic.

## Write a narrow claim

Prefer a claim another reader can inspect: “The offer displayed [effect] in [context].” Avoid turning it into “This always gives [effect]” without evidence covering that wider statement.

Record the source URL, section or timestamp, observation date, review date, build, and run context separately. If a page cites a screenshot you have not inspected, say you are citing the guide rather than claiming direct verification.

## Compare choices fairly

1. Define the question and outcome before collecting results. Use an outcome the game actually displays or one you can measure consistently.
2. Choose a baseline and one change to investigate. Record unavoidable differences rather than hiding them.
3. Keep build, mode, difficulty, character, and persistent bonuses as consistent as practical.
4. Log every attempt, including failed or interrupted runs. State exclusions and why you made them.
5. Report the count of attempts and variation. A small sample is exploratory; do not convert it into a universal tier list.
6. Separate descriptive results from a recommendation. Explain how player skill, random offers, or unknown modifiers may affect the interpretation.

No damage, reward, stacking, or drop-rate formula is supplied by this starter kit. Do not manufacture one by multiplying interface values whose relationship has not been established.

## Resolve conflicting observations

Keep both source records while checking build, language, mode, difficulty, character, progression, and screen context. A translation difference or a changed offer may explain a disagreement. If the cause remains unclear, mark the claim unresolved and state what new evidence would settle it.

Do not silently overwrite an old result with a new one. Add a dated correction or a new record and link the records together.

## Before publishing

- Link each factual claim to a source and its context.
- Label translated text, inference, and personal preference.
- Treat `unknown` as meaningful missing information.
- Check permissions before attaching any third-party media; a public URL does not grant redistribution rights.
- Remove account identifiers, local paths, personal files, save data, and credentials.
- Use [CONTRIBUTING.md](../CONTRIBUTING.md) for the review checklist.
